# TVBox 自用接口

一条地址填进 TVBox（影视仓 / OK影视 / 派清新等均可）：

```
https://ghfast.top/https://raw.githubusercontent.com/wlongdan/tvbox/main/config.json?r=1
```

备用（内容一样，主地址打不开时换这条）：

```
https://gh-proxy.com/https://raw.githubusercontent.com/wlongdan/tvbox/main/config.json?r=1
```

说明：`raw.githubusercontent.com` 在部分网络被拦；`cdn.jsdelivr.net` / `fastly.jsdelivr.net` 的 `@main` 走长缓存，实测返回的是几周前的老版本，清缓存也刷不掉，所以不用。直播清单已写成绝对地址，不依赖相对路径解析。

## 里面有什么

- **点播 9 站**：全部是直连采集中转（`type=1`），不用 jar、不用账号，列表与详情秒开，播放地址不带 `auth/token/sign` 签名，搜索可用。
- **直播 51 个频道**：央视 19 台（CCTV-1~17、CCTV-5+、CGTN）＋卫视 32 台（含深圳卫视）。同一个频道名写 1–3 条线路，TVBox 会把它们合并成一个频道，**节目列表只显示 51 个干净的台名，播放界面可以自己切线路**。

## 直播线路怎么用

1. 只有一个分组「央视卫视」，51 个频道，列表里只显示台名，不会出现「线路1/高清/备用」这类备注。
2. 每台带 1–3 条线路（37 个台有 2 条以上）。播放时按菜单键、或在播放界面点「线路」，就能自己切；**线路1 是自检排出来的最优线路**（首包快、分片 3–8 秒的优先）。
3. 不用手动改配置：某台的首选线路连续 2 天不通，自检会从池子里换一条当天能通的上来，其余线路原样保留。

线路池的实际状况（2026-11-28 第三次实测）：**51 个台全部拿到实测可播线路**，每台 3 条可选、共 301 条可用，首选线路 m3u8 首包中位 71 ms、首分片中位 192 ms、分片中位 5.0 秒，51 台分片全部 ≤8 秒。

这一轮换掉了主要来源：参考 `best-fan/iptv-sources` 与 `vbskycn/iptv` 两个每日自动更新的仓库，取它们的运营商 IPTV 通道（`tsfile/live/...` 这套，走的是各省运营商 CDN）与省级播控源，在本机宽带逐条实测后按首包/分片排序。GitHub 自检侧同时能测到 47/51 可用。

已排除的坏源：16×16 假高清（`8.138.7.223`）、码率撑不住的 4K（`event.pull.hebtv.com` 的 4K 变体）。

## 自动维护

仓库每天 05:07（北京时间）自检一次，由 GitHub Actions 在 GitHub 自己的服务器上执行——不用你开机、不用打开豆包、不依赖任何设备：

- 9 个点播站逐个请求列表接口，只上报状态，**不自动移出站点**（机房与家宽的可用性差异太大，避免误删）；哪个站连不上会写在 `last-check.md`。
- 每站每个分类都查一次真实条数，**条数为 0 的分类自动从菜单里删掉**；接口异常或剩不到 2 个分类时跳过该站，避免误清空。
- 直播测 `live.m3u` 的 51 条现用线路 + `live-pool.m3u` 的后备线路；某台现用线路**连续 2 天不通**，才从池子里换一条当天测通的上来，换不动就保持原样，**绝不删台**。
- 有变化就提交，没有变化也会更新自检记录（`last-check.md`、`state.json`）。
- 当天可用站点不到一半、或直播可用线路不到两成，判定为网络异常，**整轮不做任何调整**。

所以你电视上这条地址不用改，失效的源会被自动换掉。
